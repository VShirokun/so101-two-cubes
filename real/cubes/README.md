# Двухцветные кубы с ArUco-метками (реальный стенд)

Кубы для автоматической записи реального датасета: CV читает позу куба по
меткам, скриптовый эксперт берёт куб через IK, цвета кубам добавляет
перекраска на постпроцессинге (кубы физически чёрно-белые).

Генератор: `python3 make_cubes.py` → `out/`. Самопроверка внутри: каждая
грань обязана детектироваться OpenCV и в номинале, и с учётом зазора.

## Что в out/

| Файл | Что это |
|---|---|
| `cubes_2color.3mf` | **одна модель сразу двух цветов**: оба куба в сборе, тела с назначенными экструдерами (1 = белый, 2 = чёрный) — для Bambu Studio + AMS |
| `cube_1color.3mf` | **одноцветный куб без меток**: тот же куб 28 мм одним телом — печатать цветными филаментами, чтобы иметь реальные цветные кубы для проверки политики (сборщику датасета они не видны — он работает по меткам) |
| `cube{A,B}_body_white.stl` | белая деталь: куб 28 мм с карманами 0.8 мм на 6 гранях |
| `cube{A,B}_inlays_black.stl` | 6 чёрных вкладышей-«ключей» (лежат лицом ВНИЗ, в порядке граней +Z −Z +X −X +Y −Y) |
| `preview_cube{A,B}.png` | какая грань — какой ID (вид снаружи) |
| `render_2color.png` | сборная двухцветная модель (вид с двух сторон) |
| `render_1color.png` | одноцветный куб глазами Bambu Studio (миниатюра её реэкспорта — доказательство, что студия читает файл) |
| `manifest.json` | словарь, ID, фреймы меток на гранях — исходник для CV-кода |

Куб A — ID 1–6, куб B — ID 7,10,11,13,14,15 (словарь `DICT_4X4_50`; берутся
только ID со связной чёрной областью, иначе вкладыш распался бы на части).
Маркер 21 мм, модуль 3.5 мм, белое поле 3.5 мм до ребра.

## Вариант 1: одна двухцветная модель (Bambu Studio + AMS)

Открыть `cubes_2color.3mf` в Bambu Studio: оба куба уже в сборе, белые тела
на филаменте 1, чёрные — на филаменте 2 (зарядить белый в слот 1, чёрный в
слот 2). Проверено: студия читает файл и сохраняет назначения тел
(`python3 check_2color.py` — структурная проверка + реэкспорт через CLI
Bambu Studio; мультицветный слайс в headless-CLI не проверяется — эта версия
CLI не делает смен филамента даже на фирменном мультицветном калибровочном
файле, так что цвета видны в GUI).

Замечания:
- предупреждение «объект не manifold» при импорте — норма для этой
  геометрии из стыкующихся боксов (как модели из Tinkercad); «исправить» или
  игнорировать — слайсится однозначно;
- включить «Flush into objects' infill» — промывка при сменах цвета уйдёт в
  заполнение кубов вместо отходов;
- цена сборной печати: смена филамента почти на каждом слое (~140 слоёв),
  дольше и с расходом на промывку; цветовые границы на боковых гранях —
  послойные, чуть волнистее, чем у вкладышей. Для эталонного качества лицевых
  поверхностей меток печатать вариант 2 (вкладыши).

## Вариант 2: раздельные детали (любой принтер, один цвет за запуск)

- **Белые кубы** — белый матовый PLA, 3 периметра, заполнение 15–20 %,
  печать как есть (гранью на пластину), поддержки не нужны. В слайсере один
  STL содержит несколько соприкасающихся тел — не разделять, слайсер сварит
  (Prusa/Orca/Bambu делают это сами).
- **Вкладыши** — чёрный матовый PLA (матовый — меньше бликов для CV),
  100 % заполнение, печатать как лежат: лицом к пластине. Гладкая/PEI
  пластина даст ровное лицо метки. Включить компенсацию «слоновьей ноги»
  (elephant foot compensation ≈ 0.15 мм), иначе первый слой расплющится и
  вкладыш не сядет.

## Вариант 3: одноцветные кубы (`cube_1color.3mf`)

Открыть в Bambu Studio, выбрать филамент нужного цвета — и печатать; чтобы
получить несколько цветов за один запуск, добавить клоны куба и каждому
назначить свой слот AMS. Проверка та же: `python3 check_2color.py
out/cube_1color.3mf` (студия перечитывает файл, меш — 12 граней, без правок).

## Сборка

Вклеить вкладыши в карманы (капля циакрина), заподлицо с гранью. Формы
карманов уникальны и не имеют поворотной симметрии: чужой или повёрнутый
вкладыш физически не встанет — перепутать невозможно, превью нужно только
чтобы работать по порядку. Посадочный зазор 0.2 мм на сторону.

## Если посадка не та

Крутить константы в начале `make_cubes.py`: `CLEAR` (зазор, мм) — туго →
0.25–0.3, болтается → 0.15; `INLAY_T` — толщина вкладыша/глубина кармана.
Размер куба `CUBE = 28` соответствует симу (`mlsim/models/so101/pick_place.xml`,
полуразмер 0.014 м) — менять только вместе с симом.
