## 2. Переезд на другую машину: переносить ничего не нужно

Решение Владимира (09.09): данные извне гита не переносятся, новая машина
пишет датасет с нуля. Для этого в гите есть всё:

- код сборщика, драйвера, автокалибровки, перекраски и конвертера (`real/`);
- интринсики обеих камер (`real/calib/c920_intrinsics.json`,
  `wrist_intrinsics.json`) — камеры те же, действительны;
- калибровка приводов lerobot — копия в
  `real/calib/lerobot_calibration/so_follower/so101_follower_vladimir.json`,
  `host/calib.py` ищет её в репозитории, если нет кэша lerobot;
- результат автокалибровки `real/calib/autocalib_real.json` — действителен,
  только если камеры и робот не сдвигались друг относительно друга; после
  переезда стенда перекалибровать (две раскладки кубов, два тура по 5 минут,
  раздел 3);
- печатные модели кубов и коробки (`real/cubes/out`, `real/box/out`).

Что теряется: 26 пилотных эпизодов (`real/data/pilot`, 3,2 ГБ) и их
перекраска — пилот, серия на 600 пишется заново. Контрольные кадры для
доводки перекраски (раздел 4.1) выбрать заново из новых записей.

Что поставить руками на новой машине:

1. conda-окружение `lerobot` (python 3.12): `lerobot==0.5.2`, `mujoco`,
   `opencv` с `aruco` (OpenCV 5), `scipy`, `pyobjc` (AVFoundation для камер на
   macOS), `ffmpeg` в PATH. Скрипты зовут `/opt/anaconda3/envs/lerobot/bin/python`.
2. Права камер (macOS): у помощника Claude нет доступа к камере, поэтому
   серверы камер запускаются из Terminal.app (`open -a Terminal <файл>.command`);
   при первом запуске система спросит разрешение у Terminal.
3. USB: обе камеры на разных портах/хабах, иначе артефакты и низкий fps.
   Камера кисти иногда отваливается по USB на движениях — сервер сам
   переподнимается; кабель стоит закрепить петлёй.

## 3. Как поднять стенд (в этом порядке)

```bash
mkdir -p /tmp/roboom_cam /tmp/roboom_wrist /tmp/roboom_arm
open -a Terminal "$PWD/real/cam/start_cam.command"     # C920, 1920x1080@30, /tmp/roboom_cam/latest.jpg
open -a Terminal "$PWD/real/cam/wrist_cam.command"     # камера кисти 640x480, /tmp/roboom_wrist/latest.jpg
open -a Terminal "$PWD/real/panel/panel.command"       # единая панель: обе камеры + рука
```

Проверка руки без движения:

```bash
cd real/arm && /opt/anaconda3/envs/lerobot/bin/python -c "from arm_driver import ArmDriver; d=ArmDriver(); print(d.read()[0]); d.close()"
```

Если стенд не двигали, калибровка `real/calib/autocalib_real.json` действует.
Если камеры или робот сдвигали — перекалибровать (две раскладки кубов, по 5 минут):

```bash
cd real/arm
/opt/anaconda3/envs/lerobot/bin/python autocalib_real.py tour --layout 1 --poses 24
# переложить кубы
/opt/anaconda3/envs/lerobot/bin/python autocalib_real.py tour --layout 2 --poses 24
/opt/anaconda3/envs/lerobot/bin/python autocalib_real.py solve
/opt/anaconda3/envs/lerobot/bin/python autocalib_real.py hover      # проверка: куб в мм от точки захвата
```

Сбор, перекраска, датасет:

```bash
caffeinate -ims /opt/anaconda3/envs/lerobot/bin/python -u collect_pilot.py --episodes 20   # кубы на 18–28 см от базы
/opt/anaconda3/envs/lerobot/bin/python recolor_pilot.py --only ep_0000 ep_0003             # или без --only — все успешные
/opt/anaconda3/envs/lerobot/bin/python pilot_to_lerobot.py --raw ../data/pilot_recolor --root ../data/lerobot/real-pilot-color --overwrite
```

Аварийный стоп руки: `touch /tmp/roboom_arm/stop` (серия прерывается на
границе эпизода, если тронуть файл в фазе взгляда). Долгие запуски — под
`caffeinate`. Средняя поза руки заслоняет ближний куб от верхней камеры —
смотреть на стол только из парковки `PARK` (в скриптах так и сделано).

## 4. Открытые задачи

### 4.1. Артефакты перекраски (приоритет 1 — Владимир видит «странные артефакты»)

Что известно по контрольным кадрам (`report-html/assets/real-pilot-recolor-v4-check.jpg`,
`-v4-stills.jpg`):
- тёмная точка/полоска у нижнего ребра куба в камере кисти на подъёме
  (тень ребра темнее 40 % белого — считается «чужим тёмным»);
- тонкая кромка не своего цвета на спуске (край маски ±2 px при ошибке позы);
- редкие остатки метки на кадрах с сильным размытием (серое ~70–80 % белого —
  ниже порога заливки 70 %);
- у корпуса камеры кисти в верхней камере остаётся окрашенная полоска шириной
  ~2 клетки рядом с видимым белым краем куба (правило «далеко от белого»);
- цвета по эпизодам раздаются случайно (в пилоте cyan 8, red 1) — для серии
  на 600 раздавать по кругу.

Идеи по порядку затрат: (а) временное сглаживание масок и поз по соседним
кадрам (куб в губках неподвижен относительно камеры кисти); (б) маска руки в
верхней камере рендером MJCF-модели руки в позе FK (окклюзия по глубине
вместо цветовых правил); (в) заливка метки не по яркости, а по гомографии
грани: внутренний квадрат метки закрашивать целиком белым грани; (г) для
границ — альфа по расстоянию до силуэта. Проверять на контрольных кадрах
через `recolor_pilot.py --only ...` и лист RAW/OLD/NEW, не пересчитывая
датасет целиком (просьба Владимира). На новых записях контрольные кадры
выбрать так: (1) верхняя камера — кадры спуска/смыкания/подъёма, где корпус
камеры кисти закрывает куб; (2) камера кисти — кадры с наибольшей долей
тёмных пикселей внутри спроецированного куба после перекраски (скрипт
выбора — в истории: сравнение V<70 внутри полигонов куба по детекции);
(3) эпизоды с наибольшим сдвигом куба в губках (`held_shift_mm` в meta).

### 4.2. Сборщик и стенд
- Промах захвата, когда верхняя камера ошибается на ~3 см (эп. 16) — доводка
  по камере кисти уже добавлена, проверить на длинной серии.
- Ложный «неуспех», когда верхняя камера не видит куб в конце эпизода
  (эп. 17) — брать позу из старта следующего эпизода автоматически.
- Кубы, откатившиеся за 28 см от базы или из зоны, сборщик не берёт (ждёт
  человека) — добавить «подтолкнуть» или расширить зону сброса внутрь.
- Камеры отдают ~17 уникальных кадров/с при записи 30 Гц (около 40 % кадров
  дубли) — либо принять, либо перейти на 15 fps в датасете.
- `mlsim/make_dataset_preview.py` на Mac требует `imageio_ffmpeg` (нет в
  окружении); превью серии делает сам сборщик (`preview.mp4`).
- Провисание руки под нагрузкой ~4 мм: цель захвата = центр куба + 6 мм, пол
  режима захвата −10 мм; на вытянутой руке (r > 0.33 м) ошибка 15 мм.

## 6. Стенд на Linux-машине с RTX 4090 (переезд состоялся 09.09.2026 вечером)

Стенд подключён к машине с 4090 (та же, где учится GR00T). Отличия от macOS:

- Рука: `/dev/ttyACM0` (адаптер CH343, `/dev/serial/by-id/usb-1a86_USB_Single_Serial_5B61032606-if00`).
  Порт принадлежит `root:dialout`; разовый доступ `sudo setfacl -m u:vshirokun:rw /dev/ttyACM0`
  (теряется при переподключении USB), постоянный — `sudo usermod -aG dialout vshirokun` + перелогин.
- Камеры: C920 — `/dev/video2` (`/dev/v4l/by-id/usb-046d_HD_Pro_Webcam_C920-video-index0`),
  кисть Sonix «USB2.0 CAM1» — `/dev/video0`. Разные USB-контроллеры. Обе отдают 30 fps по MJPG.
- Окружение: `/srv/data/vshirokun/groot-venv/bin/python` (OpenCV 4.11 с aruco, mujoco 3.11,
  scipy, pyserial). conda `lerobot` нет и не нужна: конвертер `real/arm/pilot_to_lift_v21.py`
  пишет раскладку LeRobot v2.1 напрямую (pandas + ffmpeg из imageio).
- Сервер камер — `real/cam/cam_server_linux.py` (тот же контракт latest.jpg). По умолчанию
  MJPG-пакеты камеры пишутся в файл как есть (PyAV/v4l2, 5–9 % CPU, честные 30 fps под
  обучением GR00T); `--decode` — старый путь через OpenCV, под нагрузкой проседал до 15 fps:

```bash
PY=/srv/data/vshirokun/groot-venv/bin/python
mkdir -p /tmp/roboom_cam /tmp/roboom_wrist /tmp/roboom_arm
tmux new -d -s cam_top   "cd real/cam && $PY -u cam_server_linux.py 2>&1 | tee /tmp/roboom_cam/server.log"
tmux new -d -s cam_wrist "cd real/cam && $PY -u cam_server_linux.py --name USB2.0 --width 640 --height 480 --dir /tmp/roboom_wrist 2>&1 | tee /tmp/roboom_wrist/server.log"
tmux new -d -s collect   "cd real/arm && $PY -u collect_pilot.py --episodes 80 2>&1 | tee -a ../data/collect.log"
```

- Калибровка `real/calib/autocalib_real.json` переезд пережила: первый же эпизод сборщика —
  доводка по камере кисти 3 мм, захват подтверждён, посадка 15 мм.
- **Нельзя грузить CPU, пока работает рука**: 24 процесса ffmpeg (load average 84) уронили
  сборщик таймаутом записи в порт (pyserial меряет таймаут по часам процесса). Запись в шину
  теперь повторяется один раз (`host/feetech.py`), тяжёлое — только под `nice`.
- Задача политики сужена до «взять и поднять» (перенос до коробки — алгоритмически):
  датасет режется по концу фазы `lift`, сим-проверка — `ml/gr00t/make_lift_dataset.py` +
  `eval_groot_lift.py`, обучение — `ml/gr00t/train_lift.sh`, запуск на стенде — `real/arm/run_policy.py`.

### 6.2. Сторож калибровки (не прерывает работу)

`real/watch/calib_watch.py` читает только файлы (кадры камер, `state.json` руки, meta новых
эпизодов) и раз в секунду сравнивает стенд с эталоном: фон стола в верхней камере (фазовая
корреляция по трём областям вне зоны руки, в мм по столу), опорные ArUco-метки (коробка ID 16 и
любые метки на столе, в мм по PnP), силуэт руки в парковке, силуэт губок в камере кисти, доводка
по камере кисти из каждого нового эпизода сборщика. По сочетанию признаков пишет, ЧТО сдвинулось:
камера, робот/приводы, камера кисти или объект. Пороги: 3/6 мм (фон, метки), 6/12 px (рука),
4/8 px (губки), 20/30 мм (доводка) — предупреждение/тревога.

```bash
PY=/srv/data/vshirokun/groot-venv/bin/python
$PY real/watch/calib_watch.py --snapshot          # эталон: рука в парковке, схват раскрыт, стенд проверен захватом
tmux new -d -s watch "$PY real/watch/calib_watch.py --stop-on-alert 2>&1 | tee -a /tmp/roboom_watch/watch.log"
$PY real/watch/calib_watch.py --once              # разовая проверка с печатью всех чисел
```

Статус: первая строка `/tmp/roboom_status.txt` (её показывает панель), подробно —
`/tmp/roboom_watch/status.json`, журнал `/tmp/roboom_watch/watch.log`; тревога — файл
`/tmp/roboom_watch/ALERT` с причиной, с `--stop-on-alert` ещё и стоп-файл руки (серия сборщика
завершится на границе эпизода). Проверено офлайн на записанных кадрах 10.09: одинаковый кадр и
другой эпизод — 0,2 мм; сдвиг кадра на 6 px — предупреждение 3,2 мм; на 15 px — тревога 7,3 мм с
верным разделением «камера + силуэт руки». **Наклейте на стол метку DICT_4X4_50 с ID 20** в поле
зрения верхней камеры: она отличает сдвиг камеры от сдвига робота и коробки в миллиметрах.
Эталон снимать заново после каждой перекалибровки; при переподключении C920 — тоже.
