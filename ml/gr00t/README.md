# Ветка GR00T: инструменты и порядок работы

Здесь лежит рабочий инструментарий ML-ветки Office Rover (VLA-политика
GR00T N1.7 на задаче «возьми названный кубик и положи в коробку»).
Полная хроника решений и отклонений — `DEVIATIONS.md` (51 запись),
рассказ о результатах — `report-html/vla.html`.

## Действующий рецепт

```bash
python gr00t/experiment/launch_finetune.py \
  --base-model-path <база>/checkpoint-100000 \
  --dataset-path "<новые данные>:<данные базы>"   `# смесь против интерференции` \
  --embodiment-tag NEW_EMBODIMENT \
  --modality-config-path examples/SO100/so100_config.py \
  --num-gpus 1 --output-dir <выход> \
  --max-steps 20000 --learning-rate 2e-5          `# расписание lr влезает в бюджет` \
  --shortest-image-edge 256 --crop-fraction 0.95 --no-letter-box \
  --global-batch-size 8 --dataloader-num-workers 4
```

86 минут на RTX 4090, пик памяти 21 735 MiB из 24 564 (максимум по 1054 замерам, DEVIATIONS §53).

## Скрипты

| файл | назначение |
|---|---|
| `eval_groot.py` | каноническая оценка политики; `--fail-reel` собирает нарезку промахов (правило проекта) |
| `eval_groot_fsm.py` | closed-loop оркестратор: VLA + верификатор + конечный автомат с повторами |
| `probe_grasp_signal.py` | калибровка верификатора захвата по энкодеру губок |
| `train_value.py` | функция ценности на собственном опыте политики (для RECAP) |
| `pack_advantage.py` | пошаговое преимущество → метка в тексте задачи → датасет |
| `selfplay_collect.py` / `selfplay_pack.py` | сбор и упаковка собственного опыта политики |
| `dagger_collect.py` / `dagger_pack.py` | перехват эксперта из состояний ошибок политики |
| `make_soup.py` | усреднение весов чекпоинтов (проверено: вредит, см. DEVIATIONS №51) |
| `check_camera_stability.py` | проверки тракта изображений: формат, детерминизм, джиттер |
| `convert_v30_to_v21.py` | конвертация датасетов LeRobot v3.0 → v2.1 |
| `summarize_fsm.py` | сводка по прогонам оркестратора из JSON-отчётов |

## Правила оценки (иначе цифры несравнимы)

- протокол: 100 попыток на сид, 24 с, повёрнутые кубики, обе камеры 480×640,
  ранний конец эпизода; успех судит физика (`mlsim/criteria.py`);
- шум замера ±2.3 п.п. на сид: разница меньше ~3 п.п. на 600 попытках
  улучшением не считается;
- отклонить вариант — 300 попыток; заявить улучшение — 1200 попыток на двух
  независимых наборах сидов (777–782 и 783–788);
- ранжировать только по успеху, никогда по обучающему loss.
