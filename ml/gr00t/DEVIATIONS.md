4. **lerobot зафиксирован на теге v0.4.4 вместо HEAD main** (§3 ранбука: `git clone ... lerobot`).

   - раскладка модулей `lerobot.policies.*` — именно её импортирует `mlsim/eval_sim.py`

   Было по умолчанию: HEAD ветки main.

   декодируются корректно (3×240×320, диапазон 0..1), 181 кадр/с на одном воркере —
   загрузчик не является узким местом (факт: `data_s:0.002` против `updt_s:0.031` в логе).
   Гиперпараметры обучения при этом НЕ менялись.

7. **Правка `mlsim/eval_sim.py`: подключены пайплайны нормализации.** ЕДИНСТВЕННАЯ правка кода
   репозитория, вынужденная и проверяемая по `git diff`.
   Причина: в lerobot 0.4.x нормализация вынесена ИЗ политики в отдельные пайплайны
   (`policy_preprocessor.json` / `policy_postprocessor.json` рядом с весами; у `ACTPolicy`
   больше нет `normalize_inputs`/`unnormalize_outputs`). eval_sim.py подавал сырые наблюдения
   и брал сырой выход, то есть действия в НОРМАЛИЗОВАННОМ пространстве уходили прямо в `data.ctrl`.
   Доказательство на кадрах датасета (скрипт `roboom-work/diag_act3.py`):
   - без пайплайнов: средняя |ошибка| действия **0.4002**, макс **3.0182**
     (при разбросе самих действий std ≈ 0.17–0.6 — то есть выход хуже, чем шум);
   - с пайплайнами: средняя **0.0122**, макс **0.0807**.
   Что изменено: `load_policy` дополнительно возвращает `pre`/`post` из
   `make_pre_post_processors(...)`, и вызов стал `post(policy.select_action(pre(batch)))`.
   Логика успеха (физика сцены, `cube_in_bin`, критерии, журнал попыток) НЕ тронута.
   Эффект на метрике: ACT 0/10 → 1/10 (до правки рука вообще не касалась кубиков).

8. **Добавлен `--rename_map` для SmolVLA** (в `ml/03_train_smolvla.sh` его нет).
   Причина: первый запуск упал сразу —
   `ValueError: Feature mismatch ... Missing features: ['observation.images.camera1','camera2','camera3']
   Extra features: ['observation.images.top','observation.images.wrist_cam']`.
   Базовые веса `lerobot/smolvla_base` ожидают ключи камер `camera1..3`, у нашего датасета —
   `top`/`wrist_cam`. `--rename_map` — способ, который предлагает сам lerobot в тексте этой ошибки.
   Сопоставление: `top → camera1`, `wrist_cam → camera2` (проверка в `policies/utils.py:245`
   пропускает случай «камер датасета меньше, чем ждёт политика», поэтому camera3 не нужна).
   Лог упавшего запуска сохранён: `roboom-work/smolvla-train-failed-featuremismatch.log`.
   На оценку правка не влияет: `rename_map` сохраняется внутрь препроцессора
   (`lerobot_train.py:271`), поэтому `eval_sim.py` переименует ключи сам.
